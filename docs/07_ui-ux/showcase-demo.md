# XK Logistics｜離線合成互動展示手冊

展示入口為既有 Showcase Hub 的 `/logistics/`。這是三角色操作示範，不是真實物流系統：沒有帳密登入、後端或正式客戶資料；資料只在此分頁記憶體。公開發布版本與是否更新完成，以[交付收據](../09_testing/showcase-demo-validation.md)為準。

## 開啟與角色

使用「展示角色」切換管理員、調度員與司機。桌面與手機均可透過頁首「返回展示中心」離開 Demo；離開後此分頁記憶體流程不會儲存。管理員／調度員可使用訂單、調度、異常、確認與結案介面；司機只呈現合成司機本人的展示任務。角色切換會保留同一分頁目前的操作結果，便於跨角色走完劇本；這不構成正式身分驗證。

所有資料均應使用合成內容。照片只可加入內建示意，不提供本機檔案上傳；請勿輸入真實客戶、聯絡或司機資料。離開、刷新或重置後，展示資料不會送往伺服器復原。

## 完整劇本

1. 管理員／調度員進入「訂單工作台」，開啟 `DEMO-LOCAL-1001` 草稿，查看或編輯貨物與運輸任務後儲存，再執行展示受理。另有 IMPORT／EXPORT 合成草稿可比較不同單型。
2. 在「調度工作台」選擇合成司機、主車及選用拖板後派工。同一任務不可重複派工；占用中的人車不可同時派給其他任務，前置任務未完成時後段不能指派。這只模擬流程，不代表正式資格已核准。
3. 切換司機至「本人運輸任務」，回報出發，加入內建合成照片並明確選取，再提交進度。第二階段另加入並選取照片後，可進到待完成；加入照片本身不等於提交進度。
4. 如要練習異常，司機回報合成異常，管理端要求補件；司機加入本次要求的合成照片並明確提交後，管理端再處置。補件提交不等於異常解除，處置不等於任務完成。
5. 司機確認完成及解除占用；完成照片集合沿用最後一次進度的選擇。未完成階段、有未解異常或未明確確認時不能完成。完成後資源可再用，依賴任務可繼續，但整單尚未結案。
6. 管理員／調度員於「確認與結案」記錄管理確認，待整單任務均完成及確認、沒有有效占用或未解異常後，再執行展示結案。

## 重置與手機

「重置展示」會先要求確認；取消保留目前結果，確認後恢復合成種子。刷新或另開分頁會建立獨立記憶體流程；不使用 Cookie、localStorage、sessionStorage、IndexedDB 或背景同步保存業務資料，也不刪除同來源其他展示的資料。

手機可先切換展示角色，再由導覽進入相同工作台。表格可在自己的區域內捲動；主要操作應維持可點擊尺寸，頁面本身不應橫向溢出。示意照片不是現場照片，正式紀錄不會因展示按鈕而異動。

## 本機建置

```sh
npm ci
npm --prefix frontend ci
npm --prefix frontend run build
npm --prefix frontend run build:showcase
node tests/showcase/assert-build-separation.mjs
npm run test:showcase
```

瀏覽器測試使用已安裝的相容 Playwright Chromium；首次安裝依專案版本執行 `npx playwright install chromium`。正常 `frontend/dist/` 與展示 `frontend/dist-showcase/` 分離，不提交生成輸出。正式產品仍按 README／Docker 啟動，不能把展示作為認證或後端替代。
