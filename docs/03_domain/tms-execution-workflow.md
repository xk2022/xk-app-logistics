# M4 運輸執行流程｜採用基準
依 [Q41–Q47](../98_decisions/2026-11-26-m4-execution.md)；承接 [M3 派工](tms-dispatch-workflow.md)。

- TMS 擁有執行進度、事件、異常與占用；TOM 擁有訂單／任務來源及結案；FMS 擁有行政來源；UPMS 擁有身份授權。跨模組透過既有服務邊界。
- 建議執行階段：待出發 → 已出發 → 執行中 → 待完成確認 → 已完成。各階段由明確命令觸發，拒絕逆轉、跳步、過期版本、失效指派；實作前定義精確 enum 與轉移矩陣。異常及補件獨立記錄而非覆蓋進度。
- 每次操作重新取得有效登入者及本人綁定、有效指派與來源版本；管理角色與資料範圍由伺服器判斷。不得新增未授權角色。已出發的撤派／改派不得以 M3 通用動作破壞實際占用，未定例外拒絕。
- 照片證據為個別不可變關聯資料，補件新增紀錄，非替換原始證據；缺少必要證據、處理中或失敗的上傳不算完成。
- 完成與資源釋放需同交易、同次指派且有安全解除確認；持續持有資源直到條件滿足，失敗全回滾。前置依賴只接受真實已完成／已交接證據，不因狀態或時間推測通過。
- 訂單結案須再次確認必要任務及全部阻擋異常，與派工及回報併發時不可產生矛盾。結案不是單一司機操作。
- 正式派工資格維持 UNCONFIRMED；僅隔離合成策略可走正向整合流程，正常環境仍拒絕未核准派工及改派。FMS AVAILABLE 不代表可合法派工。

詳細狀態、資料及 API 精確契約應在各工作包先核對既有程式後記錄；不破壞原 API 或舊資料。

## M4-01 可執行轉移

本包列舉 WAITING／DEPARTED／IN_PROGRESS／AWAITING_COMPLETION／COMPLETED，只開放 WAITING→DEPARTED；沒有列舉以外的自訂狀態、任意 PATCH 或跳步 API。出發後新 M3 撤改拒絕、占用保持；原成功管理命令重播仍回歷史收據。新 DRIVER 命令先重驗本人及目前有效指派，再取得歷史收據；出發不解前置任務。[精確定義](../98_decisions/2026-11-26-m4-01-engineering.md)。

## M4-02 受控進度與私有照片

依[本包工程採用](../98_decisions/2026-11-26-m4-02-engineering.md)新增 DEPARTED→IN_PROGRESS→AWAITING_COMPLETION 兩個相鄰命令。照片上傳只建立原始不可變證據，不推進版本；進度以同次指派／目前 phase／execution version 的明確 VERIFIED 照片集合檢核，成功事件保留選照關聯。照片、進度及回放均重驗本人原 Session／目前綁定／來源與完整占用，不以舊 actor 或 UUID 當授權。

正式照片規則及 provider／保存仍 UNCONFIRMED；獨立 policy/provider 預設拒絕依賴動作。只有隔離合成策略可正向驗證，原照片與歷史收據不覆寫。AWAITING_COMPLETION 不是完成或安全釋放；本包不解前置／資源，不處置例外或結案。完整操作 UI 留 M4-06。
